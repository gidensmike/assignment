Project Objective

To build a professional, single-page portfolio that introduces a student profile, showcases skills, services, and projects, and links out to every other assignment. The portfolio also serves as the homepage of the assignment showcase, so it must feel premium, load instantly, and work on every screen.

Problem Statement

Most student portfolios are plain resumes copied into a page. The challenge was to design something that looks like a real product while staying built entirely with vanilla HTML, CSS, and JavaScript — no frameworks, no libraries, no build tools.

Planning Process

The design was planned mobile-first using a single-column layout that expands to a two- and three-column grid. A Frontend Mentor style structure was used as inspiration — hero, about, skills, services, projects, contact — then customized with personal information, a blue accent palette, and the project's shared design tokens.

Data Structure Used

The carousel slides and skills are defined in the HTML and driven by the DOM. The theme preference is the one piece of persistent state, stored as a string in Local Storage under a data-theme attribute.

Why This Structure Was Chosen

Because the content is static and small, semantic HTML is the simplest and most maintainable data source. Local Storage was chosen for the theme because it survives page reloads with almost no code, and a CSS-variable-driven theming system means the whole page re-themes without JavaScript touching the DOM.

JavaScript Concepts Used

DOM Manipulation Event Listeners Local Storage IntersectionObserver Conditionals ClassList

Scroll-spy highlights the active nav link as the user scrolls; reveal-on-scroll uses an IntersectionObserver; the carousel animates a track with CSS transforms; and the theme toggle reads and writes Local Storage.

HTML Structure

The page uses a hero, a sticky pill sub-navigation, and one section per area (About, Skills, Services, Projects, Contact). Icons are inline SVGs, cards are article elements, and every section has an aria-labelledby heading for screen readers.

CSS Design Decisions

All colors live in CSS variables so Light and Dark mode swap with a single attribute change. Glassmorphism is applied to cards and the navigation using backdrop-filter; shadows are layered for depth; and clamp() sizes typography fluidly so it scales between phone and desktop without media queries.

Responsive Design Strategy

Mobile-first: base styles target small screens, then min-width media queries promote the layout to 2 and 3 columns. Grids use repeat() with minmax(0, 1fr) so cards never overflow, and every container clips overflow horizontally.

Functions Created

applyTheme()

Writes the chosen theme to the document root and Local Storage.

toggleTheme()

Reads the current theme, flips it, and re-applies it.

updateActiveLink()

Scroll-spy that highlights the section currently in view.

Program Flow

User opens page ↓ Theme script reads Local Storage ↓ CSS variables re-theme the page ↓ Observer reveals sections on scroll ↓ User clicks a nav link → smooth scroll + active state

Algorithm — Theme Persistence

const key = "assignment-showcase-theme";
function applyTheme(theme) {
  document.documentElement.setAttribute("data-theme", theme);
  localStorage.setItem(key, theme);   // survives reloads
}

Challenges Encountered

Getting the carousel to loop without a visible jump required duplicating slides and snapping the track back when the transition ends. Dark mode flash on load was solved by inlining a small script in the head that applies the theme before first paint.

Future Improvements

Add real project images, a contact form backed by an API, page transitions between sections, and a print-friendly resume layout.

Conclusion

The portfolio proves that a framework-free, mobile-first page with CSS variables, glassmorphism, and a little DOM scripting can feel like a modern product while remaining fully accessible and responsive.

Tip — because everything is token-driven, adding a new color scheme is just one new :root block.

Project Objective

To read a fixed set of products, calculate a complete shopping bill, and present the results as cards, a table, summary statistics, a price chart, and a receipt — using only arrays and loops.

Problem Statement

A shop has a fixed list of products and prices. The program must find the total, the most and least expensive items, identify products above ₦3000 and below ₦2000, and display a formatted receipt — all without a database.

Planning Process

Two parallel arrays were defined first: products (names) and prices (numbers), where index i in one corresponds to index i in the other. Every feature was then expressed as a single loop over that shared index.

Data Structure Used

Arrays Parallel Arrays Index Pairing

Why This Structure Was Chosen

Two parallel arrays keep the data flat and the logic simple — exactly what the assignment asked for. Name and price stay linked by position, and a single index variable drives every loop, which makes the relationship between products and prices impossible to break by accident.

JavaScript Concepts Used

Loops Arrays Running Totals Conditionals Comparisons DOM Manipulation

Functions Created

calculateTotal()

Loops the prices array, adding each price to a running total, and returns it.

findMostExpensive()

Compares every price, tracking the highest, and returns its index.

findLeastExpensive()

Same comparison logic but keeps the lowest price and returns its index.

aboveThreshold()

Filters products whose price is greater than ₦3000 into a new list.

belowThreshold()

Filters products whose price is less than ₦2000.

generateReceipt()

Walks both arrays and formats the itemized bill and totals into the DOM.

Explanation of Every Function

calculateTotal()
  • Purpose: compute the full bill.
  • Parameters: the prices array.
  • Return value: a number (the sum).
  • Logic: for each price, add it to total; after the loop, return it.
  • Output: displayed in the receipt total.
findMostExpensive()
  • Purpose: locate the priciest product.
  • Parameters: the products and prices arrays.
  • Return value: the index of the most expensive item.
  • Logic: loop, compare each price to the best seen so far, keep the greater.
  • Output: the product name shown in the summary card.

Program Flow

User clicks "Calculate" ↓ Functions loop over both arrays ↓ Total, min, max and filters are computed ↓ Receipt is rendered into the DOM ↓ Statistics and chart refresh

Algorithm — Running Total

let total = 0;
for (let i = 0; i < prices.length; i++) {
  total += prices[i];   // accumulate
}
return total;

Challenges Encountered

Keeping the two arrays in sync when writing comparisons — the solution was to always operate on the shared index and to store the winning index rather than the value alone, so the product name and price could both be read afterwards.

Future Improvements

Replace the parallel arrays with an array of product objects, add a live search, and compute the bill with Array.prototype.reduce().

Conclusion

This assignment shows how a tiny amount of data and a few well-written loops can power a surprisingly complete checkout experience with no framework at all.

Note — reduce() can replace the manual running-total loop in one line.

Project Objective

To manage a class of students — add, remove, search, and update scores — while keeping averages, PASS/FAIL status, and statistics live on a dashboard.

Problem Statement

Storing each student's details in separate variables would make the code impossible to loop over. The data needed one container that could grow, shrink, be searched, and be summarized.

Planning Process

Each student was modelled as an object with id, name, age, and score. All students were stored in one array, and every feature (add, remove, search, update, statistics) was written as a function operating on that array.

Data Structure Used

Objects Arrays

Why This Structure Was Chosen

An object groups related attributes into one meaningful record, and an array gives the collection order, length, and access to push(), splice(), and search loops. Together they model a "list of records" — the natural shape for a class register.

JavaScript Concepts Used

Objects Arrays Functions push() splice() return Loops Array Searching

Functions Created

addStudent()

Validates the fields and pushes a new student object onto the array.

removeStudent()

Finds the student's index and removes it with splice().

findStudent()

Searches by id and returns the matching object or null.

updateScore()

Locates the student, reassigns the score, and re-derives the grade.

calculateAverage()

Sums every score in a loop and divides by the count.

Explanation of Every Function

addStudent()
  • Purpose: register a new student.
  • Parameters: name, age, score.
  • Return value: the new student object (or null if invalid).
  • Logic: build an object, validate, then students.push(obj).
  • Output: a new row in the table.
removeStudent()
  • Purpose: delete a student by id.
  • Parameters: the student id.
  • Return value: true if removed, false if not found.
  • Logic: find the index with a loop, then students.splice(index, 1).
  • Output: the row disappears and statistics update.
findStudent()
  • Purpose: look up one student.
  • Parameters: the student id.
  • Return value: the object, or null.
  • Logic: loop until the id matches; return immediately when found.
  • Output: the profile card is populated.

Program Flow

User submits the form ↓ Function validates and mutates the array ↓ renderTable() redraws the table ↓ Statistics recompute from the array ↓ UI refreshes everywhere

Algorithm — Add & Remove

const students = [];

function addStudent(name, age, score) {
  students.push({ id: nextId(), name, age, score });
}

function removeStudent(id) {
  const i = students.findIndex(s => s.id === id);
  if (i !== -1) students.splice(i, 1);
}

Challenges Encountered

Removing the right student required careful index handling — removing by id instead of by position avoids mistakes when the list is filtered or sorted. Updating a score also needed to re-derive the grade so badges never went stale.

Future Improvements

Persist students in Local Storage, add editing in place, and sort the table by score with one click.

Conclusion

The student manager demonstrates the power of objects plus arrays: one data structure, five focused functions, and a dashboard that stays perfectly in sync with the data.

Warning — always search by a unique id, never by array position, once the list can change.

Project Objective

To manage a small library — add, remove, borrow, return, and search books — with an available/borrowed breakdown and live statistics.

Problem Statement

Books need multiple attributes and two states (available vs borrowed). The system must keep those states correct while letting users filter and search without corrupting the data.

Planning Process

Each book became an object with id, title, author, and an available boolean. Borrowing and returning were designed as state flips, and the shelves were defined as derived views — filters over the same array.

Data Structure Used

Objects Arrays Filtering Searching

Why This Structure Was Chosen

An object per book keeps related attributes together, and a single array means "available" and "borrowed" are not separate copies of the data — they are two filtered views of the same source, so they can never disagree.

JavaScript Concepts Used

Objects Arrays Functions Filtering Searching push() splice()

Functions Created

addBook()

Pushes a new book object, available by default, onto the array.

removeBook()

Finds the book by id and removes it with splice().

borrowBook()

Sets available = false for the matching book.

returnBook()

Sets available = true back for the matching book.

searchBook()

Case-insensitive match against title or author.

getAvailableBooks()

Filters the array to books whose available flag is true and returns a new array.

Explanation of Every Function

borrowBook()
  • Purpose: check a book out.
  • Parameters: the book id.
  • Return value: true on success, false if missing.
  • Logic: find the book, set book.available = false.
  • Output: the book moves to the borrowed shelf.
getAvailableBooks()
  • Purpose: list only available books.
  • Parameters: none (uses the books array).
  • Return value: a new array of available books.
  • Logic: books.filter(b => b.available).
  • Output: the "Available" shelf and count.

Program Flow

User clicks "Borrow" on a book ↓ borrowBook() flips the state flag ↓ Shelves re-filter the same array ↓ Counts and charts refresh

Algorithm — Filtered Views

const books = [
  { id: "BK-001", title: "Eloquent JS", available: true },
  { id: "BK-002", title: "CSS Secrets", available: false },
];

function getAvailableBooks() {
  return books.filter(b => b.available); // new array, source intact
}

Challenges Encountered

Borrowing a book that was already borrowed could create inconsistent state — solved by checking the flag and toasting an error. Returning a new array from getAvailableBooks() kept the source safe from accidental mutation.

Future Improvements

Track due dates and borrower names, add covers, and persist the catalog in Local Storage.

Conclusion

The library manager shows how a boolean flag plus array filtering produces two perfectly synchronized shelves from one source of truth.

Tip — deriving views with filter() removes whole classes of synchronization bugs.

Project Objective

To build a shopping cart where items can be added, removed, and quantity-adjusted, with subtotal, VAT, total, a receipt, and analytics — all updating live.

Problem Statement

A cart needs mutable quantities per item and precise money math. The tricky parts are keeping quantities in sync everywhere and calculating money accurately without floating-point errors.

Planning Process

Each cart entry was modelled as an object with name, price, and quantity. All entries live in one array, and every mutation was isolated into its own function so no other part of the code can accidentally change the cart.

Data Structure Used

Objects Arrays Functions

Why This Structure Was Chosen

An object naturally holds name, price, and quantity, and the array gives order plus easy search by name. Small pure functions around the array create a clear, predictable API for the UI to call.

JavaScript Concepts Used

Objects Arrays Functions return Conditionals Loops DOM Manipulation Template Strings

Functions Created

addItem()

Adds an item, or bumps its quantity if it already exists.

removeItem()

Removes an item by name; returns true if removed.

increaseQuantity()

Increments an item's quantity by one.

decreaseQuantity()

Decrements the quantity, removing the item at zero.

calculateSubtotal()

Sums price × quantity across all items.

calculateVAT()

Applies the VAT percentage to the subtotal.

calculateTotal()

Adds subtotal and VAT.

findMostExpensiveItem()

Finds the line with the highest price × quantity.

displayReceipt()

Formats the itemized bill, totals, and footer into the receipt card.

Explanation of Every Function

addItem()
  • Purpose: put an item in the cart.
  • Parameters: name, price, quantity.
  • Return value: the updated cart.
  • Logic: if the name exists, add to its quantity; otherwise push a new object.
  • Output: the cart cards and table re-render.
calculateSubtotal()
  • Purpose: total value of all lines.
  • Parameters: the cart array.
  • Return value: a number.
  • Logic: sum price * quantity for every item.
  • Output: shown in the summary and receipt.
calculateVAT()
  • Purpose: compute tax on the subtotal.
  • Parameters: subtotal, VAT rate.
  • Return value: a number.
  • Logic: subtotal * (rate / 100).
  • Output: the VAT line on the receipt.

Program Flow

User clicks + / − / Remove ↓ A cart function mutates the array ↓ Calculators return subtotal, VAT, total ↓ DOM re-renders cards, table, summary ↓ Receipt refreshes with every change

Algorithm — Subtotal with reduce()

function calculateSubtotal(cart) {
  return cart.reduce(
    (sum, item) => sum + item.price * item.quantity,
    0
  );
}

Challenges Encountered

Money precision — solved by computing with raw numbers and rounding only at display time via a naira() formatter. Allowing a quantity to hit zero created ghost items, so decreaseQuantity() removes the line at zero.

Future Improvements

Add discount codes, persist the cart in Local Storage, and render the receipt in a printable view.

Conclusion

The cart shows why functions that return values beat functions that print: every calculator is reusable, testable, and composes into a live, always-accurate receipt.

Note — returning values instead of printing inside functions keeps the logic free of side effects.

JavaScript Concepts Explained

The building blocks used across every assignment, in plain English.

Arrays

A list of values kept in order. Used to hold students, books, cart items, and products.

Objects

A record with named properties. Used to group related attributes like a student's name and score.

Loops

Repeating work over a collection. Used to sum totals, search lists, and build receipts.

Functions

Named, reusable blocks of logic that take input and return output. The core of every assignment.

push()

Adds an item to the end of an array. Used by addStudent(), addBook(), and addItem().

splice()

Removes items from an array at a given index. Used by removeStudent() and removeBook().

return

Hands a value back to the caller. Keeps functions pure and lets results be displayed later.

Conditionals

Decisions with if/else. Used for PASS/FAIL, thresholds, and quantity checks.

DOM Manipulation

Reading and updating the page. Used to render tables, cards, receipts, and stats.

Local Storage

A tiny key-value store in the browser. Used to persist the theme across reloads.

Event Listeners

Code that runs when the user interacts — clicks, submits, key presses — driving every dashboard.
